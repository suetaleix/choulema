# 抽了马 V8 产品、功能与 UI 总规划

## 1. 产品目标

核心是可免费体验的实时 3D 抽奖系统。用清晰、完整、自然的游戏交互吸引用户体验与注册；通过新增皮肤、机台及专业功能获得增值收入。付费不改变随机结果和中奖概率。

四个用途固定为「抽吃什么 / 抽玩什么 / 抽奖品 / 抽点名」。用途决定候选与规则，机台决定演出，主题决定材质、背景、光效和可选声音。活动选择只输出活动名称，不扩展为攻略、行程或活动管理。

V8 是已上线产品的整理版本：不增加未确认的玩法，不重做已经认可的机台和音色。版本号只在健康检查、管理和交付信息使用，不在抽奖舞台放置装饰版本号或无意义序号。

## 2. 页面与交互

| 主页面 | 职责 | 二级入口 |
|---|---|---|
| 登录介绍页 `/login.html` | 展示玩法、免费价值、3D 机台和账号入口 | 怎么玩、免费与升级、注册、邀请规则 |
| 玩法页 `/play.html` | 满屏游戏舞台，进来就能玩 | 候选/规则、机台/外观、记录、偏好、配置、账户、卡密、邀请、订单 |
| 超管页 `/admin.html` | 账号、收费和运营管理 | 总览、商品、订单、权益、卡密、邀请、内容、系统、审计 |

根路径进入介绍页；游客可直接免费玩。已登录用户仍能阅读介绍。超管入口按页面后缀进入，所有管理请求在服务端校验权限；不以隐藏链接作为安全措施。既有大屏、支付回跳、玩法参数继续兼容。

2026-10-07 账号入口更新：新注册以邮箱为主，只填邮箱、密码、邮箱验证码，账号 ID 自动生成，不再收集手机号。登录支持邮箱及账号 ID；旧账号继续可用，不清空原数据。超管按邮箱或账号 ID 查询，展示验证状态。验证码与邀请奖励同事务完成；具体规则、配置和验收见 [邮箱注册方案](EMAIL_REGISTRATION_20261007.md)。本次先本地验收，通过用户确认后再部署。

玩法过程：选用途 → 改候选（可选）→ 选机台/主题（可选）→ 点击或空格 → 加速与持续运转 → 减速并指向服务端结果 → 金色结果提示 → 再抽或返回机台。抽取不会自动打开设置。

进入页面默认最高画质和完整动效，不因手机、系统减少动态效果或旧本地偏好自动变成简洁模式。手动简洁/低画质只影响当前页面。完整演出时收起操作面板，保留可唤出的退出控制；浏览器不允许原生全屏时使用页面内满屏。输入框、设置弹层、结果操作保留原生空格与焦点行为。

## 3. 固定功能范围

| 用途 | 基础操作 | 已有进阶能力 |
|---|---|---|
| 抽吃什么 | 菜名/餐厅候选、预设、随机/不重复、排除 | 保存个人配置；不含下单 |
| 抽玩什么 | 活动候选、双人/宅家/运动预设、随机/不重复 | 保存与复用；不生成安排 |
| 抽奖品 | 奖品库存、人数、抽奖品/为奖品抽人 | 年会多奖项、跨奖项不重复、品牌、演练、弃奖补抽、导出 |
| 抽点名 | 名单、不重复、多人、随机分组 | 班级/课次、续用课次、统计、导入导出 |

服务端保存结果、轮次、库存和操作幂等键。名单同名使用稳定 ID 区分。名单或规则变更需按现有轮次规则处理；同一场次切换外观不能清空记录。候选耗尽时明确提示新开一轮。多人结果分页展示，并可查看或复制完整结果。

| 机台 | 候选上限 | 单次结果上限 | 呈现 |
|---|---:|---:|---|
| 经典转盘 | 48 | 1 | 指针固定，盘面与标签旋转，减速准确停在结果 |
| 胶囊机 | 1000 | 50 | 胶囊仓内滚动碰撞、出球揭晓；动画展示数量按渲染预算控制 |
| 姓名星球 | 1000 | 50 | 所有参与姓名组成空心球，无连线，球体转动；支持分组 |

上限来自现有接口和内容目录，不等同于所有设备的高帧率承诺。只读大屏不能获得主持权限，丢失主持页面后通过明确接管恢复。

## 4. 视觉与声音基线

整体风格：简洁、大气、科幻。全屏背景与机台统一，移除黑色展示底座和黑框舞台。控件低干扰，结果名称在提示框中使用金色；机台候选和三维结果保留各主题原色。

默认主题与星空主题均覆盖三台机台。星空转盘固定为已确认的透明极光星盘：透射玻璃盘、连续薄外圈、青紫光幕、切面四芒星核、上方指针、少量流光。没有齿轮、密集铆钉和圆点拖尾。文字跟随盘面，获选文字在指针下正向可读。

胶囊的过程必须实际滚动，姓名球过程必须转动；主题装饰随真实速度、减速和揭晓变化，不以短闪光替代完整过程。避免廉价高亮、白色遮挡和遮住姓名的粒子。切换与结束释放模型、纹理、音源和循环。

| 主题 | 三种已批准的可选音效 | 使用规则 |
|---|---|---|
| 默认 | 经典叮当 / 霓虹街机 / 糖果弹珠 | 免费基础主题内选择 |
| 星空 | 星铃幸运 / 银河流转 / 极光礼赞 | 星空主题内选择，独立记住选择 |

音效以启动、过程节奏、停稳、揭晓四层构成。过程跟随机台真实运动；转盘使用过格节奏，胶囊和姓名球按现有事件协议。不得恢复持续马达嗡鸣、摩擦噪声或高频随机杂音。音效素材使用已批准 v3 文件及哈希清单；试听、静音、音量、离页停止继续有效。三种声音是主题内部选择，不作为三份收费商品。

桌面、平板、手机竖屏和横屏分别保留可达的主操作、候选、外观和退出控制。面板独立滚动，关闭按钮不随内容消失；安全边距兼容异形屏。实际性能和软键盘行为仍按真机验收。

## 用户反馈与持续升级（2026-10-09）

继续保持登录介绍、玩法、超管三个主页面。登录介绍页底部增加「问题与建议」；玩法页账号面板提供同一入口，游客也能反馈，不占用演出舞台。反馈免费，付费身份不影响提交、回复或处理可见性。

用户可提交「遇到问题 / 优化建议 / 其他反馈」，填写 5–2000 字描述和可选联系邮箱；可选择附带当前页面、用途、机台、主题、屏幕尺寸，不自动收集名单、结果、完整网址。提交后获得编号，在「我的反馈」查看状态和回复；游客记录保存在服务端并绑定本浏览器身份，首次登录按既有独占归属规则转入账号。

后台「用户反馈」支持类型、状态、内容/编号/联系邮箱筛选、分页、公开回复和内部备注。状态为待处理、跟进中、已采纳、已解决、已关闭；可重新跟进。解决或关闭须给用户说明；已采纳表示进入规划，不表示功能已经发布。运营总览显示待处理数量。内部备注、管理员身份、联系信息不出现在用户反馈列表。

当前不支持附件上传和自动邮件通知；填写邮箱仅用于必要联系，界面明确说明回复在站内查看。后续按真实反馈考虑截图附件、更新版本关联和自助找回密码，不把这些未实现项目宣传为已交付。验收与发布门槛见 [本轮检查](FEEDBACK_ACCEPTANCE_20261009.md)。

## 5. 免费、商品与权益

免费注册、三台首发基础机台和默认完整演出长期保留，不按抽取次数收费。账号价值是保存/找回配置、记录、订单和权益。主题可完整演练预览；免费入口不因后续增值内容上架被收回。

| 商品 | 初始价格 | 期限与范围 |
|---|---:|---|
| 星空主题 `cosmic` | ¥9.90 | 365 天，三台机台的星空外观与主题内三种声音 |
| 专业功能 `pro` | ¥99.00 | 365 天，以当前目录的专业能力为准 |
| 后续机台/主题/功能包 | 未定 | 按单独已交付内容定价、登记兼容范围和权益 |

这些是初始价格，运营后台当前已保存价格优先。按年购买是手动续期，不自动扣费。后台调整价格生成新版本，旧订单保留金额与权益快照。专业功能会员不默认包含所有未来皮肤和机台。

会员与指定皮肤的卡密分开生成，可选月卡 30 天、季卡 90 天、年卡 365 天、自定义 1–3650 天，支持批次、数量、备注、兑换截止、导出和未用卡作废。新月卡/季卡在线售价必须先确认，不从卡密期限自动推断。

同项权益以来源分别记账：购买、卡密、邀请、人工补偿。续期累加，撤销只影响对应来源，不误删其他已购期限；到期后保留历史和配置。

## 6. 邀请与管理

邀请链接/海报引导好友免费体验和注册。默认规则模板为有效新注册奖励邀请人 30 天 `pro` 与 30 天指定皮肤（当前 `cosmic`），实际条件以后台发布活动版本为准。是否新用户同赠、是否需要首次体验、月度上限和活动日期分别配置。不会把建议默认值写回已经运营中的活动。

归因、防重复、自邀拒绝、规则快照、并发幂等和双权益发放在服务端处理。异常可核验、补发或按来源撤销。共享网络只能作为风险信号，不直接判定课堂或家庭作弊。不做现金返佣、多级分销或强制拉新解锁基础体验。

超管覆盖：账号搜索/启停/安全重置密码；商品价格与上下架；订单、支付宝查单/补偿/全额退款；权益来源；卡密；邀请活动版本/记录；介绍和 FAQ；维护与销售开关；备份任务及审计。保护当前管理员和最后一位超管，敏感操作记录原因。

金额用整数分。运营净额是本站已确认数据，不冒充支付宝结算到账；不确定退款和部分退款进入人工复核，不擅自撤销权益。

## 7. 支付、安全和扩容

支付宝直连电脑网站支付、手机网站支付；保留 RSA2 验签、主体/金额校验、订单快照、幂等发权及返回后的主动查单。生产商户配置和 `LOTTERY_CARD_SECRET` 存服务器私有目录，永不随源码分发。支付可用性按目标商户和部署环境验收，不能由本地模拟替代。

V8 继续使用专用服务账号、反向代理 HTTPS、单进程应用与外置 SQLite。请求体、验证码和部分高成本入口有限流；来源校验、安全响应头、图片解码白名单和导出公式转义已纳入代码。多实例前先改共享验证码/限流与数据库，不直接增加 workers。

升级采用新发布目录、独立依赖、正式库一致性备份和原始记录校验，保留上一版本。代码回退继续使用当前数据，不以旧库覆盖后续新订单。真机、长期性能、异地备份恢复和资金结算复核作为持续工作，详见 [验收基线](ACCEPTANCE.md)。
